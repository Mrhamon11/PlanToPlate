{% comment %} Reusable share modal (design.md, "UI": "A reusable share modal ... visibility radio, user multi-select, current-shares list with revoke buttons"). Same modal shell as _confirm_delete.html: loaded via hx-get into a modal target for JS users, or rendered as the content of a full page for a no-JS fallback. Usage: include this partial "with object=... share_url=... unshare_url=... shareable_users=... cancel_url=...". `object` must be owned by the current user — the /share/ and /unshare/ REST actions this posts to are IsOwner-only (core/permissions.py) and would 403 for anyone else, and the /shares/ action returning the same audience list this modal displays is IsOwner-only too (design.md: "the audience list is itself sensitive"). That second point is why the ownership check below is not merely a caller contract: the whole modal body is gated on `user.is_authenticated and object.owner_id == user.id` so that if a caller ever includes this partial unconditionally (or a future screen forgets _ownership_badge.html's "only offer this for Mine" rule), a non-owner gets an empty render instead of the full sharee list — the same disclosure the API's own IsOwner gate on /shares/ exists to prevent. `object.shared_with.all` below is therefore only ever reached once that check has already passed. {% endcomment %} {% if user.is_authenticated and object.owner_id == user.id %}
